Argon2 메모리 행렬

Argon2는 메모리를 lane × 열의 행렬로 잡고, 블록 하나를 만들 때마다 직전 블록과 이미 만들어진 블록 중 하나(참조)를 압축 함수 G에 넣습니다. 참조를 고르는 방식이 d/i/id를 가릅니다. 블록 값은 시각화용 32비트 믹서의 가짜이고, 채우는 순서와 참조 규칙은 RFC 9106을 따릅니다.

참조 블록을 고르는 세 가지 방식

Argon2d는 직전 블록의 첫 32비트를 J₁, 다음 32비트를 J₂로 씁니다. 세 변종 모두 J₂ mod p로 참조할 lane을 고르고(첫 패스 첫 슬라이스는 자기 lane), J₁로 그 lane 안의 위치를 고릅니다. 값을 계산해 보기 전에는 어디를 읽을지 알 수 없어서 메모리를 전부 들고 있어야 하지만, 같은 기계의 다른 프로세스가 캐시 접근 패턴을 엿보면 비밀번호 정보가 샙니다.

Argon2i는 J₁·J₂를 (패스, lane, 슬라이스, 전체 블록 수, 패스 수, 변종, 카운터)만으로 G를 두 번 돌려 만듭니다. 비밀번호와 무관하니 접근 패턴이 새지 않지만, 공격자도 패턴을 미리 알 수 있어 메모리를 줄이는 공격(Alwen–Blocki, CRYPTO 2016)이 어느 정도 통합니다. RFC 9106 §7.2는 1 GiB·3패스 기준 비용을 약 3분의 1로 줄인다고 적습니다.

Argon2id는 첫 패스의 앞 두 슬라이스만 i 방식, 나머지는 d 방식입니다. 비밀번호가 메모리 접근에 영향을 주기 시작할 때쯤이면 이미 메모리 절반이 i 방식으로 채워져 있어 사이드채널 이득이 작고, 뒤 절반은 d 방식이라 메모리 하드성이 살아납니다. RFC 9106과 OWASP의 기본 권장입니다.

J₁에서 실제 위치를 뽑을 때는 x = J₁²/2³², y = |W|·x/2³², z = |W| − 1 − y처럼 제곱을 써서 최근 블록이 더 자주 뽑히게 편향시킵니다(RFC 9106 §3.4.2). W는 오래된 블록부터 줄 세우는데, 둘째 패스부터는 현재 슬라이스 바로 다음 슬라이스(이전 패스 값)가 가장 오래된 쪽입니다. 위 애니메이션에서 참조가 계산 중인 블록 근처에 몰리는 이유입니다.
